# Prompt: Build a Gmail Connector

Build a Gmail connector in my project that lets users connect their Google account so my app can read, search, send, and manage their emails on their behalf. Use Google OAuth 2.0 with the Gmail REST API — this is the same method Manus AI uses for their Gmail connector.

The user flow should work like this: the user clicks a "Connect Gmail" button in my app, gets redirected to Google's OAuth consent screen where they sign in and approve permissions, then Google redirects them back to my app with an authorization code. My app exchanges that code for an access token and a refresh token, stores the refresh token encrypted in the database, and from that point on can call the Gmail API on the user's behalf by refreshing the access token whenever it expires.

Before writing any code, the app needs to be set up in Google Cloud Console. Create a project, enable the Gmail API from the API library, configure the OAuth consent screen as "External" user type with the app name and contact info, and create OAuth 2.0 credentials of type "Web application" with the redirect URI pointing to your callback endpoint. Save the Client ID and Client Secret as environment variables.

For scopes, use sensitive scopes only — do not use the restricted full-access scope `https://mail.google.com/` because that requires a third-party security assessment costing around $500 per year and annual re-verification. Instead, use `https://www.googleapis.com/auth/gmail.modify` for read, send, and label management, along with `https://www.googleapis.com/auth/userinfo.email` and `https://www.googleapis.com/auth/userinfo.profile` to get the user's email address and name. If you want more limited access, you can use `gmail.readonly` for read-only, `gmail.send` for send-only, or `gmail.compose` for drafting and sending.

Build these API routes: A connect endpoint that constructs the Google OAuth URL with the scopes, `access_type=offline`, and `prompt=consent`, then redirects the user to Google. A callback endpoint that receives the authorization code from Google, exchanges it for tokens by posting to `https://oauth2.googleapis.com/token`, fetches the user's profile info, and stores everything in the database linked to the current user. A status endpoint that returns whether the user has an active Gmail connection and which email is connected. A disconnect endpoint that revokes the token by posting to `https://oauth2.googleapis.com/revoke` and removes the stored credentials.

For the actual Gmail functionality, build these: A messages list endpoint that calls `GET https://gmail.googleapis.com/gmail/v1/users/me/messages` with support for Gmail search queries like `is:unread`, `from:someone@example.com`, or `has:attachment`. A single message endpoint that fetches a full message with body, headers, and attachments using `format=full`. A send endpoint that constructs a raw RFC 2822 email message, base64url encodes it, and posts it to `https://gmail.googleapis.com/gmail/v1/users/me/messages/send`. A drafts endpoint for creating drafts using the same message format. A labels endpoint that lists all labels. And a modify endpoint that adds or removes labels from a message for actions like archiving, marking as read/unread, or moving to trash.

For token management, build a token manager that checks if the access token is expired before each API call, and if so refreshes it by posting the refresh token to `https://oauth2.googleapis.com/token` with `grant_type=refresh_token`. Cache the new access token with its expiry. If the refresh fails with `invalid_grant`, that means the user revoked access, changed their password, the token was unused for 6 months, or the app is in testing mode and the 7-day token expired — handle all of these by marking the connection as disconnected in the database.

For the database, store per user: the connected Google email address, display name, encrypted refresh token, cached encrypted access token, token expiry timestamp, granted scopes, connection status (connected, disconnected, or expired), and timestamps for when it was connected and last updated.

The environment variables needed are: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, and an `ENCRYPTION_KEY` for encrypting stored tokens.

Security is critical since you're dealing with private emails. Encrypt all tokens at rest in the database. Never expose tokens to the frontend — all Gmail API calls must happen server-side. Use a `state` parameter in the OAuth flow to prevent CSRF attacks by generating a random string, storing it in the session, and verifying it on callback. Always use HTTPS in production. Require user confirmation before sending any email — show a draft preview first. Never log email body content, only metadata like subject line, sender, and the action taken. Gmail API has rate limits of 250 quota units per second per user, where most reads cost 5 units and sends cost 100 units — handle 429 responses with exponential backoff.

For the UI, build a simple connector settings section: a "Connect Gmail" button when not connected, the connected state showing the Gmail address and connected date, a "Reconnect" button for re-authentication if the token expires, and a "Disconnect" button that revokes access and clears stored tokens.

For production deployment beyond 100 test users, you'll need to submit your app for Google's OAuth verification. Sensitive scopes take 3-5 business days to verify. You'll need to provide a YouTube demo video showing the OAuth flow and how user data is used, a privacy policy URL, and your app's homepage URL. During development, you can add up to 100 test users in the OAuth consent screen settings who can connect without verification.

Reference documentation: Gmail API overview at https://developers.google.com/workspace/gmail/api/guides, Gmail API scopes at https://developers.google.com/workspace/gmail/api/auth/scopes, Google OAuth 2.0 for web servers at https://developers.google.com/identity/protocols/oauth2/web-server, OAuth consent screen setup at https://support.google.com/googleapi/answer/6158849, sensitive scope verification at https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification, and the Gmail API messages reference at https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages.
